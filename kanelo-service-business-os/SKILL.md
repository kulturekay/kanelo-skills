# Kanelo Service-Business OS

This skill is the routing layer over Kanelo's service-business knowledge base. It does **not** restate the source material. It tells you which reference file to open for a given decision, how to apply it to Kanelo's situation, and what every output must contain before it goes to Caleb.

The source material lives in `references/`. Read only the file(s) relevant to the task. Each reference is a detailed playbook; do not load all 14 at once.

---

## 1. When to use this skill

Consult this skill **before** producing any of the following:

- market research
- niche selection
- IACP / ICP
- offers or pricing
- outreach
- sales scripts
- pipeline plans
- onboarding plans
- delivery systems
- retention plans

If a task touches how Kanelo finds, signs, serves, or keeps customers, start here.

## 4. Kanelo positioning rules

Apply these to every recommendation, regardless of which reference you used.

Kanelo does **not** sell "AI agents" as novelty.

Kanelo helps founder-led service businesses turn scattered tools, messy operations, and ad hoc AI usage into **reliable operating loops that create measurable business outcomes**.

When the source playbooks suggest a tactic, translate it through these priorities:

- outcomes over workflows
- customer evidence over ideas
- revenue over demos
- repeatability over novelty
- integration and ownership over tool hype
- research before outreach
- paid validation before software

If a tactic in a reference conflicts with these priorities, flag the conflict in the output rather than following it blindly.

---

## 5. Output requirements

Every output produced using this skill must explicitly state, in this order:

1. **Source files used** — which reference(s) in `references/` informed the work.
2. **Stage** — where this sits in the Kanelo operating sequence.
3. **Assumptions made** — what was taken as given.
4. **Evidence still missing** — what would need to be true and is not yet confirmed.
5. **Decision or recommendation** — the actual call.
6. **Caleb approval required** — yes/no, and for what specifically.
7. **Next action** — the single next step.

Do not bury these. Put them at the top or bottom of the output as a clearly labelled block.

---

## 6. Approval rules

Agents **may**: research, summarize, compare, draft, score, and recommend.

Agents **may not**, without Caleb's explicit approval:

- contact customers
- publish externally
- send outreach
- change pricing
- commit to deadlines
- spend money
- change strategy

When a task would cross one of these lines, stop at the draft/recommendation stage, mark "Caleb approval required: yes," and describe exactly what you would do on approval.
